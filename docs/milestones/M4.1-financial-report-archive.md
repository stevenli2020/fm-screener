# M4.1 - Persistent SGX financial-report archive (CLOSED)

## Approval

- Status: Closed
- Approved by: project owner
- Approval date: 2026-08-14
- Acceptance symbol: Z74 (Singapore Telecommunications Limited)

## Objective

Create a persistent, incrementally growing archive of SGX financial statements for later
M5 company assessment. The archive supplements M4's short-window announcement feed; it
does not replace that feed and performs no AI analysis.

## Delivered scope

- Added `scripts/download_financials.py`, a WSL-compatible targeted collector for one SGX
  universe symbol per invocation.
- Uses the authoritative symbol mapping in `scripts/sgx_announcement_filters.json` and
  preserves each mapping's required SGX filter type: `company` or `securityname`.
- Queries only SGX category `ANNC17` (Financial Statements and Related Announcement) over
  an inclusive requested date range.
- Excludes only `Notification of Results Release` listing rows. Quarterly, half-yearly and
  full-year financial-result announcements remain eligible.
- Downloads every attachment from an eligible announcement into source-specific staging,
  then classifies it deterministically from extracted PDF text.
- Archives primary financial statements and supplementary management financial analysis;
  confirmed releases and presentations are removed from staging.
- Retains uncertain documents under `_review` rather than deleting them.
- Stores accepted reports directly under `reports/financials/<symbol>/<year>/`. Stable SGX
  source IDs are included in filenames and the manifest, not used as archive directories.
- Writes a valid JSON `manifest.json` and continues to read the earlier JSONL format for
  migration.
- Supports historical range expansion and skips previously processed announcements by
  stable SGX source ID before opening details or downloading attachments.
- Added `--debug` progress output and explicit summary counts for downloaded, archived,
  rejected and review-required attachments.

## Attachment classification policy

| Classification | Persistent treatment | Deterministic evidence |
| --- | --- | --- |
| `primary_financial_statement` | Archive and expose to later M5 work | At least three core statement sections, or an explicit financial-statement filename supported by statement content |
| `supplementary_financial_analysis` | Archive separately by manifest classification | Explicit Management Discussion and Analysis or Operating and Financial Review content |
| `presentation_or_release` | Remove local staged files; retain audit metadata | Explicit release/presentation content, or a strong filename hint with no core-statement content |
| `needs_review` | Retain under `_review` | Missing, empty, unreadable or inconclusive extracted content |

The confidence label describes document-type classification only. It is not an investment,
trading or factual-confidence score:

- `high`: extracted text directly proves the document type;
- `medium`: filename/context contributes to the decision because extracted text is
  incomplete or does not contain a direct type marker; and
- `low`: evidence is insufficient, so the document is retained for manual review.

For an unreadable attachment, an `NR`, `MR` or `MS` filename abbreviation is rejected only
when the same announcement package contains a separately proven primary statement.

## Archive and manifest contract

Example layout:

```text
reports/financials/z74/
|-- 2022/
|-- 2023/
|-- 2024/
|-- 2025/
|-- 2026/
|-- manifest.json
`-- failures.jsonl
```

Each manifest record contains the SGX source ID, announcement metadata, publication date,
announcement URL, retrieval timestamp and two attachment collections:

- `attachments`: only the primary and supplementary documents retained for downstream
  analysis; and
- `attachment_decisions`: every downloaded attachment, including its classification,
  confidence, reason, signals, SGX URL, SHA-256 hash, size and retention status.

Rejected attachments do not retain a local path. Their source URL and content hash preserve
an auditable decision and allow later re-download if policy changes.

## Mandatory M5 handoff

When M5 starts, its AI-agent analysis must use the M4.1 financial-report archive as a
first-class input alongside the M4 announcement feed. For each company under analysis,
M5 must read the symbol's `manifest.json` and include the retained primary financial
statements and supplementary management analysis documents. The extracted page-delimited
text is the preferred machine-readable input; the corresponding PDF, SGX source URL,
stable source ID and SHA-256 hash remain the provenance record.

M5 must report when a required symbol has no archived financial statements or has
documents under `_review`; it must not silently treat missing or inconclusive archive
content as complete financial coverage. The detailed M5 prompt and token-selection policy
will be defined when M5 is authorized, without changing this input requirement.

## Boundaries and follow-up work

- No AI summary, financial interpretation, sentiment analysis or trading decision occurs
  in M4.1.

  integration task and must not be reported as complete.
